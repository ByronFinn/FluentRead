# 评论助手

评论助手是划词翻译卡片里的一个动作：选中网页文字（含图片）后，在翻译卡片头部点「评论」，或在「读懂」学习方式动作行中点与 读懂/拆句/用法/练习 并列的「评论」，按你定义的风格指令生成若干条可直接粘贴到社交平台的候选评论。

## 使用

1. 设置 → 专项翻译 → 翻译卡片，开启「启用评论助手」；评论服务、模型（默认跟随当前 AI 服务）、评论条数（1–5）与风格提示词都在同一分区配置，与其他翻译卡片动作的设置同处一页。
2. 卡片内点「设置」（评论页签和读懂页签底部都有同样的入口）会直接跳转到该分区。
3. 在网页中选中文字：翻译卡片打开后，点卡片头部的「评论」，或进入「读懂」后在动作行中点「评论」切换到评论页签；划词翻译关闭时，选区指示条上会直接显示「评论」按钮。面板自动开始生成，顶部显示选区的目标语言译文（默认简体中文）；选区本身就是目标语言（如中文选区配中文目标）时，顶部直接显示原文。
4. 每条评论恒定双语：正文用选区语言书写，其下紧邻目标语言译文；选区语言与目标语言一致时单语展示。正文语言与判定不符时后台会自动对齐：正文误用目标语言且译文恰为选区语言的条目直接交换两者；无法挽救的条目丢弃——全部条目被丢弃时自动重试一次，部分丢弃时其余评论照常展示并在面板给出提示。模型漏交评论译文或选区译文时，后台会用同一服务定向补译一次（按条判定：正文已是目标语言的条目不补），选区译文与评论译文一并补齐；补译失败时评论正文照常展示，顶部回落为原文，面板底部出现「部分评论的译文生成失败，可点击重新生成」提示。
5. 每条候选右下角「复制这条」，或底部「复制全部」；「重新生成」会取消上一条在途请求后再发。

入口规则：评论入口不依赖读懂助手的开关；翻译卡片关闭（划词模式为「关闭」）时指示条仍提供「评论」入口。选区语言与目标语言相同（包括中文对中文）时评论入口照常出现。

## 提示词模型

与翻译卡片的提示词体系一致：你在设置页翻译卡片分区的「评论风格提示词」编辑器中编辑「风格指令」段，安全规则、选区包装与输出契约由代码固定，用户内容不能覆盖它们。风格指令只影响语气、视角与风格；评论语言由目标语言设置与选区语言判定决定，条数由计数器决定，两者均不受提示词影响——在提示词里写「用某语言写」「写多少条」不会生效。留空使用默认风格；`{{count}}` 占位符会替换为评论条数。

编辑器提供「预览系统提示词」开关，实时展示最终拼装的系统提示词全貌（以未识别选区语言的场景呈现；实际语言段会按选区语言自动判定注入），可直接确认风格指令的注入位置与不可覆盖的固定段。

## 结构契约

评论结果优先通过模型工具调用（`submit_comments`）返回，与阅读/写作助手使用同一套结构化输出机制；模型未调用工具时，后台会从纯文本输出中兜底解析评论负载。返回内容做宽容归一化而非一刀切拒绝：未知字段忽略、超长正文截断、无效条目跳过。仅「格式类失败」（未提交、结构无法挽救、语言全错）自动重试一次，供应商网络与鉴权错误、用户取消不重试。两次生成调用都带按选区长度估算的输出 token 上限，防止失控输出。模型未按契约提交时面板给出可重试的错误。

## 边界

- 评论结果只用于即时复制，不写入学习记录，不做本机持久化。
- 每次模型调用与其他 AI 功能一样计入「模型用量」统计（与翻译卡片归入同一用途分类），用于查看耗时与 Token 消耗。
- 风格指令属于用户配置，会随配置导出、备份与历史快照保存，处理方式与翻译卡片提示词相同。
- 选区图片经画布降采样为 JPEG（透明像素先铺白底）后随请求发送，上限 4 张、单边 1024px；表情图标自动过滤，跨域受限的图片自动跳过，只按文字生成。
- 站点禁用名单、全局开关、评论配置变更与卡片关闭都会即时取消在途请求，包括尚未完成的图片捕获。
- 后台是 MV3 service worker，空闲约 30 秒即会被浏览器终止；默认路径已迁离屏执行器（模型调用在常驻 DOM 运行时内执行，执行器内建心跳），评论级的 20 秒扩展 API 保活探测仅在回滚直连路径（设置 → 专项翻译 → 翻译卡片，把「模型调用执行位置」切到「后台直连」）生效，长生成（含云端思考模型与补译）不再因 worker 休眠而中断，单次请求上限 120 秒。
- 修改评论配置只失效评论面板的现有结果，需要点「重新生成」才使用新配置；不会影响翻译卡片的回答缓存。
